# Product

## 产品定位

AgentForge 是一个 agent 研发控制平面，不是单一 coding agent，也不是单纯的 IDE 对话增强工具。它的目标是把研发过程从“靠人逐步提示模型做事”，升级成“由系统自动拆解、派发、执行、验证、汇报”的工程流水线。

## 目标用户

- 个人开发者
- 初创团队
- 小型工程团队

这些用户通常已经在使用 Codex、Claude、Cursor 或 OpenHands 一类工具，但仍然存在以下痛点：

- 项目上下文依赖聊天历史
- 每次开新线程都要重复解释
- 任务拆分不稳定，粒度过大或过于随意
- 多 agent 协作没有清晰边界
- 测试与验收结果不结构化
- 自动化很容易停在半路，难以持续

## 要解决的问题

AgentForge 第一版要解决的核心问题：

- 上下文依赖聊天历史，导致线程切换成本高
- 任务拆分不稳定，无法形成最小闭环执行单元
- 多 agent 协作无边界，容易互相覆盖或重复劳动
- 验收、通知、blocked 结果不结构化，难以继续自动推进
- 自动化不可持续，缺少明确的状态机和人工介入边界

## 核心能力

第一版希望沉淀并验证以下能力：

- 一个高层 prompt / plan 转成任务图
- 任务被拆成原子 TaskUnit
- 多 agent 并行派发
- 自动测试、联调、验收
- blocked 分级与人工介入
- 每个步骤都能形成清晰证据与可追踪状态

## 第一版不做

为了避免过早发散，控制平面 MVP 明确不做：

- 自研模型
- 自研浏览器引擎
- 自研 CI 平台
- 完整的组织级 RBAC 实现
- 复杂商业化计费系统
- 企业级多租户控制台

## 第一版成败标准

第一版不是“功能越多越好”，而是以下 3 件事成立：

1. 新线程不依赖聊天历史，也能建立完整上下文
2. 一个高层任务可以被稳定拆成原子任务单元
3. 每个任务从派发到验收都有结构化状态和清晰边界
