# Roadmap

## Phase 1：文档与控制平面规格冻结

### 目标

- 冻结任务 DSL
- 冻结状态机
- 冻结 agent 角色与边界
- 冻结 bootstrap 机制
- 冻结知识身份、预算、生命周期与评分协议

### 完成标准

- `TASK_SCHEMA.md` 可直接作为任务 contract 使用
- `ACCEPTANCE.md` 与任务 DSL 字段一致
- `ARCHITECTURE.md` 中的状态机和角色定义不再摇摆
- 新线程只靠文档就能建立上下文
- `KNOWLEDGE_MODEL.md` 与 `KNOWLEDGE_BUDGET.md` 可直接指导知识闭环实现

### 明确不做什么

- 不实现完整服务代码
- 不接入完整 GitHub / Temporal / LangGraph 运行时
- 不做真实多 agent 调度程序

## Phase 2：最小可运行控制平面

### 目标

- 任务接收
- 任务拆分
- 并行派发
- 结果汇总
- GitHub / 飞书最小集成
- 最小知识候选捕获与预算门控

### 完成标准

- 能接收一个高层任务输入
- 能拆成原子 TaskUnit
- 能把任务分发给不同 agent 类型
- 能记录状态变化并输出结构化结果
- 能发出最小通知
- 能基于验收信号决定是否生成知识候选
- 能用 Top-K + 限流控制长期知识写入

### 明确不做什么

- 不追求多租户
- 不做完整 Web 控制台
- 不做复杂策略配置系统

## Phase 3：执行与验收闭环

### 目标

- 接入后端 agent
- 接入前端 agent
- 接入 Playwright 验收 agent
- 打通 blocked / 重试 / 人工介入
- 打通知识发布、冲突审查、归档与淘汰

### 完成标准

- 后端任务可自动执行并跑测试
- 前端任务可自动执行并跑构建或 E2E
- 联调 agent 可唤起 Playwright 验收
- blocked 有明确升级路径
- 长期知识对象具备 identity、version、scope、status
- 高价值冲突可进入 review 或人工 gate
- 低质量知识可被 deprecated 或 archived

### 明确不做什么

- 不在这一阶段追求全业务覆盖
- 不强行做复杂回滚平台
- 不做组织级审批流全量能力

## Phase 4：平台化与复用

### 目标

- 多项目模板
- 观测面板
- 成本 / 成功率统计
- 策略配置化

### 完成标准

- 可在多个项目间复用
- 有统一项目模板
- 能看到任务成功率、失败原因、agent 表现
- 策略可按项目配置，而不是写死在 prompt 里
- 能看到知识候选、发布、冲突、归档和 budget 命中情况

### 明确不做什么

- 不要求第一版就支持大组织治理
- 不要求完整商业化后台
- 不追求一开始就替代成熟 DevOps 平台
